# Beacon Ruby v1.2.0

Beacon Ruby v1.2.0 adds opt-in experimental profiling to the source distribution.
Assets are `beacon-ruby-1.2.0-source.tar.gz`, `beacon-profiling-0.1.0.gem`,
`beacon-security-0.1.0.gem`, `SOURCE.txt` and `SHA256SUMS`. The gems have independent
package versions and are distributed on GitHub, not RubyGems. Existing upstream
instrumentation gem identities and versions remain unchanged.

## Profiling

- Disabled by default; explicit gem installation and startup are required.
- CPU time, wall time, allocation counts and sampled exceptions. The optional
  Beacon native extension adds sampled live heap objects, shallow live heap
  bytes, GVL wait time and partial GVL timeline events.
- DataKit-compatible multipart pprof upload defaults to the local receiver and
  one combined 60-second export window. Shutdown flushes the actual partial tail.
  CPU and allocation share native sampling slices; values are not extrapolated.
- Independent export worker, bounded export queue and collectors, timeouts,
  explicit post-fork reinitialization, resource allowlisting and exception privacy.
- Final empty heap snapshots clear stale gauges. File exports retain each
  collection slice's actual start and duration.
- Beacon owns the heap/GVL extension. Copied/adapted helpers and designs retain
  license, notice and provenance; no Datadog package is installed or loaded.

## Validation

Linux CRuby 3.3, 3.4 and 4.0 pass profiling compilation, tests, Appraisal and gem
builds in GitHub Actions. Local CRuby 3.3.12 profiling suites pass 25 tests and
136 assertions with 93.02% Ruby line coverage. Native C branch coverage is not
measured. The earlier complete-window DataKit check accepted all combined sample
types; receiver acceptance does not independently verify workspace indexing.

Release artifacts are built from a fixed committed tree, verified with checksums and checked
through source and isolated gem installation. See the
[installation guide](../INSTALLATION.md), [profiling reference](../../profiling/README.md)
and [acceptance record](../validation/profiling-1.2.0.md).

Security 0.1.0 is unchanged from v1.1.0. Its [scope and prior acceptance](1.1.0.md)
remain applicable. Profiling is independent of the trace/Logs SDK setup.

## Limits and rollback

Profiling is experimental on CRuby 3.3+ Linux. Wall samples depend on GVL
scheduling; heap bytes are shallow sampled live memory, not RSS, cumulative
allocated bytes or complete retained graphs. GVL events are bounded observed
waits, not a complete execution timeline, and UI rendering has not been verified.
Production overhead, broader Ractor workloads, other engines and operating
systems remain unqualified. No OTLP Profiles export or general zero-code trace
launcher is introduced.

Set `OTEL_PROFILING_ENABLED=false` and restart to disable profiling. To roll back,
restore the prior verified source/gem references, application lockfile and SDK
initialization, restart and verify telemetry. v1.1.0 has no profiling gem.
