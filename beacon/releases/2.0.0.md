# Beacon Ruby v2.0.0

## Breaking Security log binding

Security now exports compact single-line schema-v2 JSON directly in the OTel
LogRecord Body. `observed_at` moves to native event time and `occurrence_id`
moves to the `event_id` log attribute. `source` remains in Body and attributes;
all other field paths, decoded values and nesting remain unchanged. There is no
SIEM envelope or `message` wrapper. Fingerprint v1 and the inventory ID algorithm
are unchanged. Queueing and retries retain event time and identity. Record byte
budgets and inventory partitioning use the final compact UTF-8 Body.

This source snapshot distributes `beacon-security-0.3.0.gem` and unchanged
`beacon-profiling-0.1.1.gem`. The source snapshot and component versions remain
independent. Security pins specification `d9d76e5a41d974d294bb596e06918bb954319bf6`.

## Installation and migration

Download the source archive, both component gems, `SOURCE.txt` and `SHA256SUMS`
from this GitHub Release. These assets are not RubyGems publication or a
zero-code trace launcher. Follow the version-pinned source installation guide.
Update consumers to read native LogRecord time and event ID. Body-only diagnostic
archives omit those values. Rollback requires source v1.3.0, Security 0.2.0 and
its matching SIEM consumer. The published profiling 0.1.1 gem is reused only after
its packaged files are verified against the unchanged profiling source.

Security remains opt-in and approximate; schema v2, fingerprint v1 and default
no-evidence filtering are unchanged. Source/CI availability is not acceptance of
all Ruby engines, platforms, rules or storage backends. Profiling remains
experimental multipart pprof HTTP export, without an OTLP Profiles claim.
