## Changes

- **Breaking:** release **beacon-security 0.3.0** with the [standard Security log binding](https://github.com/beacon-observability/beacon-security-spec/commit/d9d76e5a41d974d294bb596e06918bb954319bf6): compact, single-line schema-v2 JSON directly in LogRecord Body, without a SIEM envelope or `message` wrapper.
- Retain the unchanged **beacon-profiling 0.1.1** gem, verified against the profiling source.

## Upgrade

Update log consumers before upgrading. Parse Body once and read the relocated fields from native metadata:

| Previous field       | Read from                                      |
| -------------------- | ---------------------------------------------- |
| Body `observed_at`   | Native LogRecord event time (`time_unix_nano`) |
| Body `occurrence_id` | LogRecord `attributes.event_id`                |

- All other field paths and values stay intact; `source` remains in Body and attributes. Schema v2, fingerprint v1, inventory IDs, opt-in Security, and default `no_evidence` filtering stay unchanged.
- Body budgets use final compact UTF-8 bytes; retries preserve event time and identity. Body-only diagnostic JSONL omits native time and event ID.
- Follow the [versioned installation guide](https://github.com/beacon-observability/beacon-ruby/blob/v2.0.0/beacon/INSTALLATION.md). To roll back, restore source **v1.3.0**, Security **0.2.0**, and its matching SIEM consumer.

## Distribution

- Attached GitHub assets: source archive, both component gems, [source provenance](https://github.com/beacon-observability/beacon-ruby/releases/download/v2.0.0/SOURCE.txt), and [SHA-256 checksums](https://github.com/beacon-observability/beacon-ruby/releases/download/v2.0.0/SHA256SUMS). Source and gem versions are independent; the gems are not published on RubyGems.
- Security requires explicit Rack middleware and SDK setup and remains approximate. Profiling remains experimental HTTP multipart pprof; this is not a zero-code trace launcher or OTLP Profiles release.

## Validation

- Security CI passed **Linux CRuby 3.3, 3.4, and 4.0**. Source and separately installed Security gem acceptance passed through a real Collector on **CRuby 3.3.12**.
- Public assets passed checksum verification and Collector acceptance. The reused profiling gem's packaged files match the unchanged source. Other engines/platforms and production backend ingestion are outside this acceptance.
